Abstract

This report presents a few-shot deep-learning system for recognising handwritten Tamil characters. The system learns a metric embedding in which a letter is represented by the mean of a few example images (a prototype), so a letter can be recognised from 1 to 5 examples and new letters can be added without retraining. Eight few-shot methods and several backbones were trained and compared on a cleaned dataset of 14,205 images covering 247 letter classes. The proposed model, a Prototypical Network on an ImageNet-pretrained MobileNetV3-Large, was selected on validation loss. On 37 letters never seen during training it reaches 95.6% ± 0.4 accuracy on 5-way 5-shot episodes, 89.7% on 5-way 1-shot, and 83.3% when every query is classified among all 37 unseen letters (macro-F1 0.820). After temperature scaling its confidences are well calibrated (ECE 0.164 → 0.044). The model is exported to ONNX and runs in about 1.4 ms per image on a laptop CPU.

2. Introduction and objectives

The Tamil script has 12 vowels, 18 consonants, the āytham (ஃ) and 216 consonant-vowel compounds, giving 247 letters. Many letters differ only in a small stroke, a loop or the position of a vowel sign. Collecting large labelled sets for every letter is costly, and the compound letters are numerous. A conventional classifier also needs retraining whenever a letter is added. Few-shot learning addresses both problems. The network learns an embedding space in which images of the same letter lie close together. A letter is then described by a handful of examples rather than by trained output weights.

Objectives

  1. Audit and clean the handwritten Tamil dataset, and build leakage-free evaluation protocols.
  2. Train and compare deep few-shot methods (Prototypical, Matching and Relation Networks, Siamese/triplet, ArcFace pre-training, Baseline++, first-order MAML) against a supervised CNN baseline.
  3. Monitor training rigorously (epoch-level loss curves, overfitting and plateau detection) and choose all settings on validation data.
  4. Evaluate once on held-out test data: accuracy over N-way K-shot episodes with confidence intervals, F1, confusion analysis, calibration and open-set rejection.
  5. Deliver a deployable model (ONNX) that can enrol new letters without retraining.

Implementation: Python 3.12.0, PyTorch 2.15.0+cpu, timm, OpenCV, scikit-learn and ONNX Runtime. Hardware: Intel Core i5-1335U laptop CPU, 16 GB RAM, no GPU.

3.2 Preprocessing

One module is used for training and for inference, so the two cannot drift apart. Steps: alpha compositing on white, conversion to grey, light denoising, automatic ink-polarity detection (normalised to white ink on black), Otsu thresholding with a soft mask that keeps grey levels inside the strokes, cropping to the ink bounding box with an 8% margin, padding to a square without distorting the aspect ratio, resizing (48 px for Conv4 models, 96 px for the proposed model) and normalisation. Soft thresholding was chosen because hard binarisation broke thin strokes at this resolution.

3.3 Evaluation protocols

Protocol B (novel classes, main protocol). The letter classes are split 70/15/15, stratified by category, into 173 base classes (training), 37 validation classes (model selection) and 37 novel classes (final test). The novel letters are never seen during training. A hard-novel subset of 31 compounds contains letters whose consonant and vowel sign both appear in base classes in other combinations (for example, கொ held out while க and கோ are seen). This tests compositional generalisation.

Protocol A (known classes). Within every class, images are split 70/15/15 (train/val/test), stratified by source group. Support examples come from the train pool and queries from the test pool.

Leakage controls. Duplicates were removed before splitting. Base, validation and novel classes are disjoint (unit-tested). No image appears in both the support set and the query set of an episode. Validation uses a fixed list of episodes, so loss values are comparable across epochs. Test data was evaluated once per checkpoint, and a guard file blocks a second evaluation.

4. Methodology

4.1 Few-shot formulation

Training and testing use episodes. An N-way K-shot episode draws N letters, K labelled support images per letter and Q unlabelled query images per letter. The model must label the queries using only the support images. Classes are sampled uniformly, so every episode is class-balanced regardless of the class imbalance in the dataset.

The network learns an embedding in which images of the same letter cluster together. After training, enrolling a letter only requires computing its prototype from a few images. No weights change, so new or missing letters (for example தௌ) can be added at deployment time.

4.4 Methods compared

All methods use the same splits, the same episodes and the same training recipe:

  • Prototypical Network: mean-prototype classifier (the proposed approach).
  • Matching Network: cosine attention over all support images.
  • Relation Network: a learned module scores concatenated support/query feature maps.
  • Siamese (triplet): triplet loss with hard-negative mining; nearest-prototype decision.
  • ArcFace: angular-margin classification pretraining on the base classes. Evaluated directly, and as an initialisation for episodic ProtoNet fine-tuning.
  • Baseline++: frozen backbone with a cosine classifier fitted on each episode's support images.
  • First-order MAML: gradient-based adaptation on each episode.
  • Supervised CE classifier: conventional non-few-shot reference (Protocol A only).

Two further techniques were evaluated as separate result rows: transductive refinement (soft k-means on the unlabelled queries) and temperature scaling.

4.5 Evaluation metrics

Episode accuracy is the mean over ≥ 600 test episodes with a 95% confidence interval (FO-MAML: 100 episodes), for N ∈ {5, 10, 20, all} and K ∈ {1, 2, 3, 5, 10}. The full-set evaluation classifies every test query among all test classes with 5 support images each, and reports accuracy, top-3/5, macro and weighted F1, per-class precision/recall/F1 and the confusion matrix. Calibration is measured by expected calibration error (ECE, 15 bins) before and after temperature scaling. Open-set performance is measured by AUROC and rejection rates.

5. Training monitoring and model selection (validation data only)

Every run logged training and validation loss and accuracy per epoch, together with learning rate, gradient norms, embedding norms and prototype separation. Automatic detectors flagged overfitting (training loss falling while validation loss rises for 3 epochs) and plateaus. No run triggered the overfitting detector. In every run the best validation epoch was the last or second-to-last.

5.1 Epoch budget

A 40-epoch study (ProtoNet, Conv4, early stopping off) shows validation loss decreasing until epoch 36 (0.2215). Validation accuracy rises from 92.32% at epoch 15 to 93.72%. The recommended budget is therefore about 44 epochs. Compute limits restricted the compared runs to 15 epochs and the proposed model to 8, so all reported test numbers are conservative.

Across 3 seeds, ProtoNet (Conv4) reaches 94.4 ± 0.3% at 5-way 5-shot and 87.6 ± 0.1% at 5-way 1-shot, so differences under about 0.5 points between Conv4 methods are not significant. FO-MAML is evaluated on 100 episodes per cell, so its intervals are wider; its 5-shot accuracy falls below its 1-shot accuracy, which indicates an unstable inner loop.

  • Few-shot vs supervised. On known letters (Protocol A), episodic ProtoNet beats the supervised CE classifier at 5-way 5-shot and when classifying among all 247 letters, using the same backbone.
  • Known vs novel letters. At 5-way 5-shot the gap between Protocol A and Protocol B is under one point, so the embedding transfers to unseen letters almost as well as to seen ones.
  • Method choice. With a small backbone, ProtoNet, Matching Net and ArcFace → ProtoNet are statistically tied. ArcFace pretraining gives the best Conv4 validation loss. Relation Net, Siamese and Baseline++ fall behind on the harder all-way task.
  • Backbone. The pretrained MobileNetV3 is the best model at every N and K, despite only 8 training epochs.

9. Limitations

  • Compute. All training ran on a laptop CPU: small backbones, 50-episode epochs, 15 epochs for the compared methods and 8 for the proposed model. The epoch study shows validation loss still improving until about epoch 36. The reported numbers are lower bounds.
  • Ablations not run. Train-time way and shot, embedding size, distance metric, EMA, input size, ResNet-12/18 and EfficientNet-B0 were not compared because of time and memory limits.
  • Data. Every image is 48 × 48, so fine details such as the pulli dot are near the resolution limit. Some images have dark shaded backgrounds or are unusable crops. Eight letters have fewer than 15 images. Writer identity is not recorded, so the source-aware test relies on coarse file-name groups (78% are "other").
  • Labels. தெள, லெள, ளெள are stored as consonant + ெ (U+0BC6) + ள (U+0BB3), while the other 15 consonant rows use the single au sign ௌ (U+0BCC). The two spellings look identical on screen, so these classes are probably the "missing" தௌ, லௌ, ளௌ written with a different encoding. They were kept separate pending review. This also lowers the measured accuracy for the ௌ sign.
  • Open set. Rejection of unknown letters is weak at full-alphabet scale (Section 8).

10. Conclusion and future work

A complete few-shot recognition pipeline for handwritten Tamil was built and evaluated rigorously. The proposed Prototypical Network with an ImageNet-pretrained MobileNetV3-Large recognises letters it has never seen with 95.6% ± 0.4 accuracy from five examples (5-way) and 83.3% among all 37 unseen letters. Its confidences are well calibrated. It runs in about 1.4 ms per image on a CPU, and new letters can be added without retraining. The comparison shows that, in this regime, the choice and pretraining of the backbone matter more than the choice among episodic metric-learning methods.

Recommended next steps

  1. Retrain the proposed model for ~44 epochs at learning rate 3 × 10⁻³, initialised with ArcFace pretraining (the best Conv4 recipe), preferably on a GPU with 200-episode epochs.
  2. Collect more samples for the small classes (ணே ணெ ழா ழ ணு ணூ ழி ழீ) and for the ொ/ோ/ௌ family, and remove unusable images.
  3. Resolve the தெள/லெள/ளெள spelling question, and collect handwritten samples of தௌ, லௌ, ளௌ.
  4. Record writer IDs to enable a true writer-independent evaluation.
  5. Improve open-set rejection, for example with per-letter thresholds or distance-to-second-best scores.
